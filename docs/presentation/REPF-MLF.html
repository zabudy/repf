Защита проекта по MLF

REPF

Прогноз недвижимости

Модели временных рядов, оценка квартир и выбор стратегии с помощью агентов

Что покажем

Подбор модели по похожим кейсам, проверку качества и объяснение результата.

8–10 минут с демонстрацией. REPF реализует мультиагентный прогноз из задания MLF и расширяет его задачей оценки квартиры.

Источники: README.md и ноутбук «Задание для студентов по MLF».

Входные данные

Две задачи в REPF

Временной ряд

CSV с колонками date и value. Пользователь задаёт частоту и горизонт. Нужно не менее 12 наблюдаемых периодов.

Пример: квартальная цена за м² на вторичном рынке Казани, I кв. 2021 – III кв. 2026.

Оценка квартиры

Характеристики одной квартиры и JSON с ценами и признаками объектов из истории рынка. Для истории нужно не менее 40 записей.

Пример: 2 817 сделок из реестра Вашингтона, округ Колумбия. Без файла включается синтетическая история Казани.

Ввод квартиры и целевая цена разделены. Признаки включают площадь, район, этаж, этажность, год постройки, тип дома и состояние.

Временной ряд одномерный. Программа сама извлекает признаки для диагностики и поиска. Для квартиры указать характеристики оцениваемого объекта и отдельную историю других объектов. Российские примеры Чебоксар и Новочебоксарска содержат цены объявлений. Американские наборы содержат цены зарегистрированных сделок. Стоимости в USD переведены по одному курсу для демонстрации.

Источник: docs/DATA.md и backend/core/forecast.py.

Архитектура

Пять шагов расчёта

01

DataAnalyst

Готовит данные и вычисляет диагностику.

02

ModelSelector

Выбирает модель и параметры. Может вызвать LLM.

03

Forecaster

Обучает модель и строит прогноз.

04

Validator

Проверяет прогноз, метрики и диагностику.

05

Critic

Оценивает результат и даёт объяснение в агентном режиме.

Supervisor

Управляет шагами, допускает до трёх итераций в агентном режиме и при необходимости отправляет результат человеку на проверку.

DataAnalyst, Forecaster и Validator выполняют детерминированные операции. ModelSelector и Critic могут обращаться к LLM. Supervisor управляет состоянием. Пользовательский чат доступен после расчёта и работает отдельно от цепочки.

Источники: backend/agents/supervisor.py и docs/ARCHITECTURE.md.

Выбор модели

Три режима, одна проверка

РежимКто выбирает модельВызов LLM
БазовыйФиксированное правило. Сезонный наивный прогноз для ряда и Ridge для квартиры.Нет
Подбор по аналогамВзвешенное голосование найденных кейсов. Аргументы берутся из наиболее близкого кейса выбранной модели.Нет
Агенты + RAGLLM получает диагностику и кейсы, выбирает инструмент и его параметры из реестра.Да*

* При доступном провайдере. При сбое пригодный вариант выбирают по кейсам и локальным правилам.

Три режима сравнимы на одинаковом временном разбиении. В реестре для рядов есть Holt, авторегрессия и гармоническая регрессия. В табличной ветке есть Ridge, соседи, бустинг и ансамбль. Для одинаковой модели и аргументов числовой расчёт совпадёт.

Источник: backend/agents/model_selector.py и backend/core/llm/tools.py.

RAG

Как находим похожие кейсы

1 168

синтетических кейсов в cases.json

1 024 для рядов
144 для оценки жилья

  1. Фильтр по типу задачиДля ряда дополнительно совпадает частота.
  2. Два независимых поискаBM25 по описанию и Qdrant по 128-мерным векторам. При сбое векторный поиск выполняет local_pca.
  3. Пять лучших совпаденийRRF объединяет ранги. Модели, гиперпараметры и метрики берутся из базы кейсов.

В агентном режиме найденные кейсы становятся контекстом LLM для выбора модели.

Вектор формируется из статистических, лаговых и спектральных признаков с преобразованием PCA. JSON хранит описания и результаты кейсов. В Qdrant публикуются векторы и поля для фильтрации по типу, частоте или табличной цели и версии корпуса. Поле backend в трассировке подтверждает, где прошёл векторный поиск.

Источники: backend/retrieval/hybrid.py, docs/ARCHITECTURE.md и docs/DEPLOYMENT.md.

Языковая модель

Три системных промпта

ModelSelector

Выбирает один инструмент из реестра. На входе диагностика, кейсы и допустимые варианты.

select() · строка 206

Critic

Возвращает оценку от 0 до 1 и короткое обоснование по диагностике.

critique() · строка 251

Чат прогноза

Отвечает по готовому результату. Получает сводку и до шести предыдущих пар реплик.

discuss_forecast() · 174

Файл backend/core/llm/manager.py. Tool Calling возвращает имя функции и параметры, которые проверяются по схеме.

Промптов два в цепочке расчёта и один в чате. Формальная оценка, расчёт и оркестрация выполняются на Python. При работе с провайдером модель выбирают в настройках аккаунта. При нарушении схемы проект использует fallback. Чат получает только сводку и сообщения.

Источник: backend/core/llm/manager.py, строки 172–256, и backend/core/llm/tools.py.

Прогноз и качество

Проверка на отложенной истории

Ранние периоды
для обучения

Поздние периоды
для проверки

  1. Модель учится на ранней части ряда или истории квартир. Точность оценивается на известных поздних наблюдениях.
  2. MAE, WAPE и MASE показывают ошибку в исходных единицах, в процентах и относительно масштаба наивной ошибки.
  3. По отложенным ошибкам строится 80% прогнозный интервал. При сомнительном результате человек может принять, пересчитать или отклонить его.

Для квартиры проект прогнозирует месячный индекс цены за м², затем корректирует оценку с учётом параметров объекта. Временной ряд проверяется на временных окнах. Номинальные 80% интервала опираются на калибровочные остатки. Небольшая история ограничивает способность оценить будущую ошибку.

Источники: backend/agents/forecaster.py, backend/tabular/housing.py, docs/REPORT.md.

Эксперимент

100 синтетических рядов

Горизонт 50 периодов, вся доступная история. MASE, меньше — лучше.

1,065 и 1,067

Средний MASE по всем долям истории и горизонтам у подбора по аналогам и агентного режима соответственно.

В пакетной оценке агентный режим использовал детерминированный mock-провайдер.

На этом длинном горизонте оба режима с поиском улучшили результат относительно базового. На длинной истории агентный режим получил 0,768 против 0,808 у аналогов. В среднем по всем настройкам значения почти совпали. Результаты характеризуют конкретный корпус и протокол. В эксперименте не измерялся эффект настоящего DeepSeek или внедрения Qdrant.

Источник: docs/REPORT.md и docs/results/synthetic_100.csv.

Живой показ

Один прогноз за три шага

  1. Открыть «Временной ряд», взять пример Татарстанстата и задать горизонт 3 квартала.
  2. Выбрать «Агенты + RAG». В трассировке раскрыть «Поиск кейсов» и «Выбор модели».
  3. В чате под сводкой спросить, что означает MASE и как читать прогнозный интервал.

Где смотреть

backend: qdrant в трассировке подтверждает векторный поиск через Qdrant.

Тот же вход можно запустить в режиме «Подбор по аналогам» и сравнить модель и ошибки.

Открыть локальный REPF · Для чата нужен активный LLM-пресет.

Перед защитой открыть приложение, войти в аккаунт и проверить доступность LLM-пресета. Если провайдер недоступен, показать базовый режим, подбор по аналогам и сохранённый результат. Для второго примера загрузить готовый JSON квартиры и указать параметры объекта. После выполнения узнать стоимость за м² и показать факторы цены.

Источники: README.md, docs/DATA.md и docs/DEPLOYMENT.md.
